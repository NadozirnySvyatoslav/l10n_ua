# HOWTO: Електронний документообіг (ЕДО) — Вчасно

← [Назад до документації](../../README.md) · [Усі гайди](README.md)

> Як надсилати акти, видаткові, рахунки й договори на підпис через сервіс ЕДО прямо з Odoo,
> стежити за статусами й отримувати вхідні документи. Перший підключений сервіс — **Вчасно.ЕДО**.
>
> Перевірка: 🔑 **потребує API-ключа** — живий обмін вимагає токена Вчасно з опцією тарифу
> «Інтеграція». Без токена модулі встановлюються й налаштовуються, але обміну немає.

Скріншоти — у теці [`img/edo/`](img/edo/) (імена файлів вказані біля кроків).

## Модулі

| Модуль | Призначення |
|--------|-------------|
| `l10n_ua_edo` | Основа: обліковий запис ЕДО, документ ЕДО, категорії, міксин «Надіслати у ЕДО», синхронізація |
| `l10n_ua_edo_vchasno` | Провайдер Вчасно.ЕДО (API v2) |
| `l10n_ua_edo_account` | Рахунки: надсилання акта / видаткової / рахунку-фактури, рахунок постачальника з вхідного документа |
| `l10n_ua_edo_sale` | Замовлення продажу: надсилання рахунку-фактури |
| `l10n_ua_edo_agreement` | Договори: підписання через ЕДО, договір стає «Підписаним» з архівом підписів |

Встановлюйте `l10n_ua_edo_vchasno`: основа підтягнеться, а містки для рахунків, продажів і договорів
встановляться автоматично, якщо відповідні модулі вже є.

Меню: **ЕДО → Вхідні / Вихідні**, налаштування — **ЕДО → Налаштування → Облікові записи**
(лише адміністратор).

> _Скриншот:_ `00-menu.png`

## Передумови

1. **Тариф Вчасно з опцією «Інтеграція».** API Вчасно — платна опція; без неї токена немає.
   Опис можливостей — у кабінеті Вчасно: **Тарифи → Можливості інтеграції**.
2. **Токен API.** Генерується у Вчасно для пари «користувач + компанія» (від імені цього
   користувача документи й завантажуватимуться). Порядок — за посиланням «Як створити токен
   користувача» в [Інструкції до API Вчасно.ЕДО](https://docs.google.com/document/d/1yjDAensRbsY9-nujkKBPERyDG_LIAnrVzwE4Gfq0fzY)
   (посилання є і в кабінеті: **Корисне → Інструкція до API**).
3. **ЄДРПОУ і e-mail контрагентів** у картках партнерів: за ними документ іде отримувачу, а
   вхідні документи знаходять свого контрагента.

> Ключ КЕП в Odoo **не зберігається**: документ підписується у Вчасно (у веб-кабінеті чи
> застосунку). Odoo завантажує документ, стежить за статусом і забирає архів із підписами.

## Флоу 1. Підключити Вчасно

1. **ЕДО → Налаштування → Облікові записи → Створити.**
2. Назва (напр. «Вчасно — основна компанія»), **Сервіс:** Вчасно, **Токен API** — вставити
   токен, **ЄДРПОУ** — підставляється з компанії, **Імпортувати вхідні з** — дата, з якої
   брати вхідні документи.
3. **Перевірити з'єднання** — має з'явитися «Токен працює: у Вчасно N категорій документів».
4. Вкладка **Категорії → Завантажити категорії із сервісу.** Підтягнуться типи документів
   Вчасно, а для українських форм правила підставляться самі:

   | Друкована форма | Категорія у Вчасно |
   |-----------------|--------------------|
   | Рахунок-фактура (з рахунку і з замовлення) | Рахунок (2) |
   | Акт виконаних робіт | Акт наданих послуг (1) |
   | Видаткова накладна | Видаткова накладна (5) |
   | Договір | Договір (3) |
   | Акт до договору | Акт наданих послуг (1) |

   Правило можна змінити або додати своє для іншої форми.

> _Скриншот:_ `01-account.png`, `02-categories.png`

## Флоу 2. Надіслати один документ

1. Відкрити **проведений** рахунок клієнта (або замовлення, або договір) → **Надіслати у ЕДО**.
2. У майстрі вже заповнено: обліковий запис, **документ** (українські форми — першими:
   акт, видаткова, рахунок-фактура; для замовлення — рахунок-фактура; для договору — договір),
   **категорія** (з правила), назва, **ЄДРПОУ** й **e-mail** отримувача з картки контрагента.
3. **Отримувач підписує першим:**
   - вимкнено (за замовчуванням) — документ лише завантажується у Вчасно й чекає **вашого**
     підпису; підпишіть і надішліть його у Вчасно;
   - увімкнено — документ одразу йде контрагенту, який підписує першим.
4. **Надіслати** → відкривається документ ЕДО: стан, посилання **Відкрити в сервісі**,
   оригінал PDF. На формі рахунку з'являється кнопка **ЕДО** зі статусом.

> _Скриншот:_ `03-send-wizard.png`, `04-edo-document.png`

## Флоу 3. Масове надсилання

1. У списку рахунків (замовлень, договорів) відмітити документи → **Дії → Надіслати у ЕДО**.
2. Обрати документ (форму) і категорію — вони спільні для всіх; отримувач у кожного свій,
   з картки контрагента.
3. **Надіслати** → повідомлення «Надіслано у ЕДО: N з M». Документи без ЄДРПОУ й e-mail
   контрагента пропускаються й перелічуються в повідомленні — решта надсилається.

> _Скриншот:_ `05-send-many.png`

## Флоу 4. Статуси й підписаний архів

Раз на 15 хвилин (або **Синхронізувати зараз** в обліковому записі, **Оновити статус** на
документі) Odoo забирає зміни з Вчасно:

| Стан в Odoo | Статус Вчасно |
|-------------|---------------|
| Завантажено | 7000 завантажений, 7001 готовий до підпису |
| Надіслано на підпис | 7002 надісланий на перший підпис, 7010 надісланий підписантам |
| Підписується | 7003 / 7007 — не всі підписи однієї зі сторін |
| Підписано відправником | 7004 — чекає підпису контрагента |
| Підписано всіма | 7008 — накладено всі підписи |
| Відхилено | 7006 |
| Видалено | 7011 — анульований |

Коли документ **підписано всіма**, архів із підписами (ZIP) завантажується автоматично й
прикріплюється до документа ЕДО та до рахунку / договору. **Завантажити з підписами** —
кнопка на документі ЕДО.

**Договори:** надіслано → договір «На підписанні»; підписано всіма → «Підписаний» з датою
підпису, архів — у полі «Підписаний документ». Скасований договір не змінюється.

## Флоу 5. Вхідні документи

1. **ЕДО → Вхідні** — документи, які контрагенти надіслали вашій компанії у Вчасно.
   Контрагент знаходиться за ЄДРПОУ.
2. Вхідний рахунок або акт → **Створити рахунок постачальника** — чернетка рахунку
   постачальника з номером, датою й PDF у вкладеннях. Повторне натискання відкриває той
   самий рахунок.

> _Скриншот:_ `06-incoming.png`

## Для розробників: свій документ в ЕДО

Міксин `l10n_ua.edo.mixin` додає «Надіслати у ЕДО» й статус на будь-яку модель. Достатньо:

```python
class MyDocument(models.Model):
    _name = 'my.document'
    _inherit = ['my.document', 'l10n_ua.edo.mixin']

    def _edo_meta(self):
        meta = super()._edo_meta()
        meta.update({'number': self.number, 'date': self.date, 'amount': self.amount_total})
        return meta
```

Хуки: `_edo_reports()` (які PDF-форми пропонувати; українські — першими),
`_edo_partner()` (контрагент, типово `partner_id`), `_edo_meta()` (назва, номер, дата, сума,
категорія), `_edo_on_state(edo_document)` (реакція на новий стан — як у договорах).
Кнопку й масову дію додають два записи в XML — див. `l10n_ua_edo_sale`.

**Новий сервіс ЕДО** (Paperless тощо) — окремий модуль, що додає себе в
`l10n_ua.edo.account.provider` і реалізує `_<сервіс>_upload / send / fetch / incoming /
download / normalize / test / categories` — див. `l10n_ua_edo_vchasno`.

## Обмеження

- Підпис КЕП — у Вчасно. API приймає готовий відкріплений підпис (p7s), тож підписання з Odoo
  через `l10n_ua_sign` можливе — заплановано.
- Синхронізація — опитуванням раз на 15 хвилин; вебхуки поки не використовуються.
- Один підписант від компанії; погодження й кілька підписантів — налаштовуються у Вчасно.
