# Заклади охорони здоров'я

← [Назад до головної](../README.md)

Облік для медичних закладів України: пацієнти, декларації з лікарем ПМД, клінічна картка (прийоми, діагнози, МКХ-10), договори з НСЗУ та капітація, каркас інтеграції з eHealth.

Легенда статусів: ✅ Стабільний · 🟢 Робочий · 🟡 Бета · 📦 Збірка

| Модуль | Версія | Статус | Призначення |
|--------|--------|--------|-------------|
| `l10n_ua_medecin` | 19.0.1.0.0 | 📦 | Збірка стеку для медзакладів (base + patient + nszu) |
| `l10n_ua_medecin_base` | 19.0.1.0.0 | 🟢 | Тип закладу, ліцензія МОЗ, спеціалізації, ID НСЗУ/eHealth |
| `l10n_ua_medecin_patient` | 19.0.1.0.0 | ✅ | Пацієнти та декларації з лікарем ПМД |
| `l10n_ua_medecin_nszu` | 19.0.1.0.0 | ✅ | Договори з НСЗУ, пакети послуг, капітація ПМД |
| `l10n_ua_medecin_clinical` | 19.0.1.0.0 | 🟢 | Прийоми, діагнози, МКХ-10, хронічні стани, алергії |
| `l10n_ua_medecin_ehealth` | 19.0.1.0.0 | 🟡 | Каркас інтеграції з ЦК eHealth (dry-run) |

---

## Огляд

- **base** — базові довідники медичного закладу: тип закладу, форма власності, ліцензія МОЗ, ID надавача в НСЗУ та eHealth, перелік спеціалізацій.
- **patient** — облік пацієнтів та декларації пацієнт–лікар (первинна медична допомога), життєвий цикл декларації.
- **nszu** — договори з Національною службою здоров'я України, пакети медичних послуг, розрахунок капітації ПМД.
- **clinical** — клінічна картка: медичні прийоми, діагнози з МКХ-10, хронічні стани, алергії.
- **ehealth** — каркас HTTP-інтеграції з Центральною компонентою eHealth (наразі лише реєстрація декларацій, режим dry-run).

> Напрям у стадії активної розробки. Ядро (`patient`, `nszu`) реалізоване й покрите тестами; `ehealth` — каркас без реальних endpoint-ів.

---

## `l10n_ua_medecin` — Збірка 📦

Мета-модуль без власного коду. Встановлює `l10n_ua_medecin_base`, `l10n_ua_medecin_patient`, `l10n_ua_medecin_nszu`.

> `clinical` та `ehealth` до збірки **не входять** — їх встановлюють окремо за потреби.

Залежності: `l10n_ua_medecin_base`, `l10n_ua_medecin_patient`, `l10n_ua_medecin_nszu`.

---

## `l10n_ua_medecin_base` — База 🟢

Залежності: `base`, `hr`, `l10n_ua_account_base`.

**Моделі:**
- `l10n_ua.medecin.specialty` — довідник медичних спеціалізацій (код, назва, категорія: первинна / спеціалізована / екстрена / стоматологічна / реабілітація / лабораторна / інша). Унікальність коду. Стартові дані: 13 записів.
- `res.company` (розширення) — поля закладу: тип закладу (13 типів: ЦПМСД, АСМД, поліклініка, лікарня, пологовий, ЕМД, діагностичний центр, реабілітація, санаторій, диспансер, лабораторія, аптека, інше), державна/комунальна форма, номер і дата ліцензії МОЗ, ID надавача в НСЗУ, ID в eHealth, зв'язок зі спеціалізаціями.

Тести відсутні (прості довідники та поля).

## `l10n_ua_medecin_patient` — Пацієнти ✅

Залежності: `l10n_ua_medecin_base`.

**Моделі:**
- `l10n_ua.medecin.patient` — пацієнт, прив'язаний до `res.partner`. Номер медкартки (унікальний у межах закладу), дата народження, обчислювані вік та вікова категорія (5 категорій для капітаційного коефіцієнта), РНОКПП з валідацією (10 цифр), свідоцтво про народження для дітей, стать, поточна декларація та поточний лікар (обчислювані). Chatter (`mail.thread`).
- `l10n_ua.medecin.declaration` — декларація пацієнта з лікарем ПМД (Наказ МОЗ № 503). Автонумерація через `ir.sequence`. Життєвий цикл: `draft → active → terminated / cancelled`. Стейт-машина: `action_activate` (автоматично припиняє попередню активну декларацію пацієнта), `action_terminate` (вимагає підстави), `action_cancel`. Підстави припинення, дати підписання/чинності/припинення, поле UUID в eHealth (унікальне), ознака електронного підпису. Валідація дат.

**Тести** (`test_patient.py`): вікова категорія, валідація РНОКПП, унікальність картки, автоприпинення попередньої декларації, вимога підстави припинення, валідація дат. Реальне покриття основної логіки.

## `l10n_ua_medecin_nszu` — Договори НСЗУ ✅

Залежності: `l10n_ua_medecin_base`, `l10n_ua_medecin_patient`.

**Моделі:**
- `l10n_ua.medecin.nszu.package` — пакет медичних послуг НСЗУ (код + рік, унікальні разом). 10 типів пакетів, 5 моделей оплати (капітація / глобальний бюджет / за випадок / за послугу / змішана), базовий тариф. Стартові дані: 5 пакетів.
- `l10n_ua.medecin.nszu.contract` — договір з НСЗУ. Автонумерація (`НСЗУ-…`). Життєвий цикл: `draft → submitted → active → expired / terminated`, з поверненням у чернетку. Обчислення очікуваних надходжень із рядків. Chatter.
- `l10n_ua.medecin.nszu.contract.line` — рядок договору: пакет, тариф, очікувана кількість, обчислена сума. Метод `action_compute_pmd_capitation` перераховує кількість на основі активних декларацій із ваговими віковими коефіцієнтами (константи `AGE_COEFFICIENTS` за Постановою № 240).

**Тести** (`test_nszu.py`): автонумерація, повний життєвий цикл, заборона подання порожнього договору, розірвання з активного стану, обчислення сум.

**Тести** (`test_capitation.py`): зважування за віковими категоріями, ігнорування пацієнтів без чинної декларації, відсутність дії на некапітаційних пакетах, нуль за відсутності декларацій.

## `l10n_ua_medecin_clinical` — Клінічна картка 🟢

Залежності: `l10n_ua_medecin_patient`.

**Моделі:**
- `l10n_ua.medecin.encounter` — медичний прийом. 6 типів (консультація, профогляд, виклик додому, невідкладна, маніпуляція, діагностика), стани `planned → in_progress → finished / cancelled` (`action_start` / `action_finish` / `action_cancel`), скарги, огляд, лікування (Html), діагнози. Chatter.
- `l10n_ua.medecin.diagnosis` — діагноз у складі прийому, прив'язка до МКХ-10, ознаки основного/хронічного (модель оголошена у файлі `encounter.py`; `diagnosis.py` порожній).
- `l10n_ua.medecin.icd10` — ієрархічний довідник МКХ-10 (`_parent_store`), **повний класифікатор НК 025:2021** «Класифікатор хвороб та споріднених проблем охорони здоров'я» (гармонізований з ICD-10-AM; затв. наказом Мінекономіки від 04.08.2021 № 360-21, чинний з 01.09.2021): класи → блоки (з вкладеними надблоками) → 3-значні рубрики → 4- та 5-значні підрубрики, 20 145 записів (з них 16 959 — коди найнижчого рівня). Ознака `is_selectable` («допустимий як діагноз» — код найнижчого рівня); поля діагнозу та хронічного стану пропонують лише такі коди. Пошук за кодом і фрагментом назви (`display_name` з trigram-індексом). Дані — `data/nk025_2021.csv`, завантажуються ідемпотентно (`_load_nk025`) при встановленні/оновленні; 27 стартових xml-id `icd10_*` збережено й оновлено на місці. Зміна № 1 до НК 025:2021 (наказ Мінекономіки від 07.05.2024 № 11710) ще **не** застосована — текст зміни не оприлюднено в машиночитному вигляді.
- `l10n_ua.medecin.condition` — хронічний стан / діагноз пацієнта (МКХ-10, дати, ступінь тяжкості).
- `l10n_ua.medecin.allergy` — алергія пацієнта (алерген, тяжкість, реакція).

Тести: багатокомпанійність, меню, класифікатор МКХ-10 (`tests/test_icd10.py`).

## `l10n_ua_medecin_ehealth` — Інтеграція з eHealth 🟡

Залежності: `l10n_ua_medecin_patient`.

Каркас HTTP-інтеграції з Центральною компонентою eHealth МОЗ. За замовчуванням працює в режимі **dry-run** (запити пишуться в лог, у API не йдуть).

**Моделі:**
- `l10n_ua.ehealth.client` (AbstractModel) — HTTP-клієнт: читання конфігурації з `ir.config_parameter`, OAuth2 `client_credentials` (заготовка), узагальнений `_request` із логуванням, `post_declaration` (реєстрація декларації, `POST /api/declarations`).
- `l10n_ua.ehealth.request.log` — журнал запитів/відповідей API.
- `l10n_ua.medecin.declaration` (розширення) — хук `action_activate`: після активації намагається зареєструвати декларацію в eHealth (у dry-run генерує псевдо-UUID; помилки не блокують активацію).
- `res.config.settings` — налаштування API (URL, client_id, client_secret, прапорець dry-run).

> Реалізовано лише реєстрацію декларацій. Електронні рецепти (eRx) та направлення (eReferral), згадані в описі модуля, у коді **відсутні**. Реальні endpoint-и, формати запитів, автентифікація та КЕП недоступні без облікових даних МОЗ. Тести відсутні.

